# Numotirus – AI Legacy Branch

---

## Purpose

This branch contains the original Numotirus codebase as it was generated by a large language model (LLM). It is preserved here for **reference, study, and research purposes**.

This code is **not intended for production use**.

---

## Context

The Numotirus project began with an experiment: *Can an LLM design and implement a secure, decentralized, end-to-end encrypted communication framework?*

This branch represents the result of that experiment.

After evaluation, the project maintainers concluded that the code required a complete rewrite to meet the project's security and reliability goals. The current, human-led version of Numotirus lives on the `main` branch.

---

## Observations

A review of this codebase reveals several patterns typical of LLM-generated software:

- **High surface-level completeness** — The code compiles, modules are structured, and APIs are documented.
- **Frequent use of best-practice patterns** — The code adopts standard cryptographic primitives, naming conventions, and modular designs.
- **Significant depth-level issues** — Security-critical logic contains vulnerabilities that would be caught by experienced human reviewers.

---

## Notable Issues Found During Review

| Area | Observed Issue |
| ------ | ---------------- |
| Secret Management | Shared secrets stored in plaintext on disk |
| Cryptographic Configuration | Hardcoded parameters where configurability is expected |
| Protocol Integration | Two independent encryption systems used inconsistently |
| Feature Implementation | Some components exist only as placeholders |
| Audit Record | The included audit report was generated by the same AI model that wrote the code |

These are not isolated mistakes — they reflect the current limitations of LLMs in handling complex, security-sensitive software engineering tasks.
